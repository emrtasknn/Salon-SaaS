## Required final real-pilot checks

These must be executed against the real Supabase project before W11.4 can be declared PASS.

### E. Staff provisioning — REQUIRED

Create/invite a pilot staff member through the real admin flow.

Verify:

1. Auth user is provisioned/invited.
2. Profile is created for the same tenant.
3. TenantMembership is created with `STAFF`.
4. Staff record is created with `ACTIVE`.
5. The operation does not create cross-tenant records.
6. Provisioning failure does not leave an unauthorized partial state.

Record the observed result and date in the final acceptance record.

### F. Inactive staff — REQUIRED

For the real pilot staff account:

1. Set staff status to `INACTIVE`.
2. Attempt the staff-authenticated workflow.
3. Verify the inactive staff member cannot perform operations requiring active staff authorization.
4. Re-activate the staff member only after the negative test is captured.

Expected result: access is denied/fails closed according to the existing authorization contract.

### G. Tenant A/B RLS isolation — REQUIRED

Use two real pilot tenants.

Verify:

- Tenant A cannot read Tenant B tenant-owned records.
- Tenant A cannot mutate Tenant B tenant-owned records.
- Tenant A cannot use Tenant B service/staff identifiers through public booking.
- Tenant B remains unaffected by Tenant A operations.

Do not use client-provided tenant IDs as the isolation mechanism. The test must exercise the real authenticated/trusted tenant path and database RLS.

### H. Missing identity / fail-closed — REQUIRED

Verify the following real application behavior:

- no authenticated user → unauthorized
- authenticated user without trusted tenant → unauthorized
- authenticated user without tenant membership → unauthorized
- membership persistence failure → unauthorized/failure, never fallback access

No fallback tenant may be selected.

### I. Provisioning failure / compensation — REQUIRED

Exercise the existing failure/compensation path where practical.

Verify:

- the intended provisioning failure is surfaced;
- partial application records are compensated when the existing contract requires it;
- a compensation failure is surfaced as the explicit failure state;
- no unauthorized tenant membership or staff access is left behind.

Do not alter the compensation contract merely to make the test pass.

### J. Secret/config boundary — REQUIRED

Verify from repository/config inspection:

- service-role/secret keys are server-only;
- browser login uses only public Supabase configuration;
- no secret key is embedded in client bundles;
- no secret is committed to Git.

Do not paste secret values into the acceptance record.
