# Task — Salon SaaS · WP-08 Closed dates + staff/admin-created appointments

## Objective
A tenant can mark closed dates that availability excludes; staff/admins can create appointments from the calendar through the same booking engine and transactional re-check.

## Risk class
C3 — availability/booking rule change, migration, new creation path into the lifecycle.

## Context
- `docs/PROJECT_GOVERNANCE.md` §7 (bookable interval, transactional re-check, UTC + tenant timezone) and §4.
- `src/domain/availability.ts`, `src/application/booking-engine.ts`.
- `docs/P9_MVP_CLOSURE_CHECKLIST.md` "Appointment lifecycle and calendar"; `docs/AUTHORIZATION_COMPOSITION.md`.

## Scope
In: closure model (tenant-wide, optionally per staff), date-based in tenant timezone, RLS (migration); closures in availability and booking re-check; admin UI for closures; create-appointment flow in admin and staff calendars using the existing engine; customer from CRM or entered as guest.
Out: partial-day breaks (unless owner adds); recurring holidays; reschedule; overbooking override.

## Acceptance criteria
- [ ] No slots on closed dates; booking on a closed date rejected server-side even if the public flow is bypassed.
- [ ] Staff/admin creation uses the same conflict condition and transactional re-check (no separate path); server-side authorization (TENANT_ADMIN for any tenant staff; STAFF scope = owner decision).
- [ ] Timezone/DST unit tests at the closure boundary; two-tenant RLS integration test for the closure table (CI).
- [ ] **Owner decisions (stop):** (a) initial status of staff/admin-created appointments (CONFIRMED vs PENDING); (b) WhatsApp on creation; (c) per-staff closures in MVP; (d) existing appointments on a newly closed date (block or warn); (e) can STAFF create only for themselves.
- [ ] Workflow: salon-saas-planner (refine) → salon-saas-database → ⛔ owner (booking rules + migration) → salon-saas-backend ∥ salon-saas-uiux → salon-saas-qa → lint/typecheck → salon-saas-reviewer → ⛔ merge → ⛔ apply approval.

## Refined plan (salon-saas-planner, 2026-11-04)
- Findings: `createBookingEngine().create` has no callers, authorizes as CUSTOMER (staffId/customer not bound to caller), hardcodes PENDING, sends no notification, creates no access token, and its in-transaction re-check skips working hours. CRM customer list is TENANT_ADMIN-only.
- Model: `ClosureDate` (tenantId, nullable staffId, local `DATE` in tenant timezone, optional reason, createdByProfileId). Partial unique indexes per tenant-wide / per-staff date. RLS ENABLE + FORCE with the standard four tenant policies.
- Closure rule: a slot is excluded when its local start date (or the local date of `endAt - 1ms`) is closed. Pure local-date comparison, DST-safe. Conflict expression in `src/domain/availability.ts` unchanged.
- Check points: public availability + public booking in-transaction re-check, engine availability + engine in-transaction re-check (beside the WP-07 tenant-status gate).
- Creation: new `createOnBehalf` in the booking engine (TENANT_ADMIN any staff; STAFF per decision (e)); customer = verified CRM profile or guest profile; same `calculateAvailability` + repository `createAppointment` with in-transaction closure + working-hours re-check.
- Ownership: database = schema + migration; backend = domain/application/persistence + server actions; uiux = `src/app/admin/closures.tsx` + create dialogs in admin/staff calendars; qa = DST boundary unit tests + CI-only `prisma-closure-dates.integration.test.ts`.

## Owner decisions (approved 2026-11-04)
- (a) Staff/admin-created appointments start **CONFIRMED** (new initial state; transitions unchanged). Public bookings stay PENDING.
- (b) On creation, send **APPOINTMENT_CONFIRMED** through the existing pipeline when the customer has a phone; "notify customer" checkbox, default on. No new template/provider.
- (c) **Tenant-wide closures only** in MVP UI; nullable `staffId` column kept for later.
- (d) Existing PENDING/CONFIRMED appointments on a newly closed date: **warn and require explicit confirmation**; never auto-cancel.
- (e) STAFF create **only for themselves** (staffId from server context), **guest entry only** — no CRM search for STAFF.
- Buffer: a slot whose end (incl. buffer) crosses into a closed local date is **rejected**.
- Status-link access token is created for staff/admin-created appointments (parity with public booking).
- UI/server contract: `src/app/appointment-create-contract.ts`.
