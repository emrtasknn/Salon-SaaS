# Task — Salon SaaS · WP-09 Web Push (ADR-044 phase 3 / W11.11)

## Objective
Staff and tenant admins on an installed PWA receive Web Push for appointment events: multi-device, tenant-scoped, revocable, via a multi-channel NotificationService.

## Risk class
C3 — migration (`WEB_PUSH` enum value, `PushSubscription` + RLS), new dependency/provider (`web-push`, VAPID), notification routing change.

## Context
- `docs/ADR-044-NOTIFICATION-CHANNELS.md` §4.1–4.5, §6–§9 phase 3, §10.2 (`web-push` approved), §10.3 (recipients: assigned staff + all TENANT_ADMIN), §10.6 (revoke after 5 transient failures or immediately on 404/410).
- `docs/ADR-043-PWA-FIRST-MOBILE-STRATEGY.md`, `AGENTS.md` PWA/Web Push rules, `docs/W11_IMPLEMENTATION_PLAN.md` "W11.11".
- `docs/P8_PRODUCTION_READINESS_CHECKLIST.md` §F; `docs/P9_MVP_CLOSURE_CHECKLIST.md` "Notifications", "Mobile/PWA".

## Scope
In: enum + table migration; `web-push` + VAPID config (names in `.env.example`); subscribe/unsubscribe actions bound to authenticated profile + membership; per-channel independent delivery; inactive staff/deactivated members get nothing; 404/410 → revoked + cleanup; payload without PII; SW push/notificationclick handlers; permission UX.
Out: customer push; reminders; `InAppNotification` table (ADR-044 §10.1).

- [ ] ADR-044 §8 unit + CI integration tests (two-tenant RLS, inactive staff, 410 revoke); existing WhatsApp suites unchanged.
- [ ] Real-device evidence deferred to WP-13 (P7 §D).
